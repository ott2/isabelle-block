# 207. Mechanical identifier renaming: word boundary for collisions, lookahead for derived facts

**Part:** Isabelle refactoring
**Added:** 2026-07-03

## When it applies

You are renaming a family of identifiers by text substitution across a codebase
(a scripted refactor): stripping a suffix, changing a prefix, de-tagging a set
of lemma/constant names. Two failure modes bite a naive `s/OLD/NEW/g`.

## What to do

Anchor each replacement with a leading word boundary AND a trailing
*negative-alphanumeric lookahead*: `re.sub(r"\bOLD(?![A-Za-z0-9])", NEW, text)`.

1. **Leading `\b` stops prefix collisions.** When `OLD` is a prefix of another
   name (`Foo` vs `Foo_Bar`, `wrap_delta` vs `wrap_delta_extra`), matching each
   *full* name renames `Foo` without corrupting `Foo_Bar` — the boundary refuses
   to end mid-identifier. (Process longest-OLD first as belt-and-braces.)
2. **Trailing `(?![A-Za-z0-9])`, not `\b`, catches derived names.** Renaming a
   *definition* silently renames its whole family of tool-generated facts —
   `X_def`, `X.simps`, `X.induct`, `X.cases`. A trailing `\b` matches `X.simps`
   (boundary before `.`) but **misses `X_def`**: `_` is a word character, so
   there is no boundary between `X` and `_def`, and the reference is left
   dangling. A negative-alphanumeric lookahead ends the stem while still firing
   before `_def` — it treats `_` / `.` as "still the same fact family".

## Why / what it avoids

It avoids two silent breakages: (a) a prefix name mangled into a shorter one
(`Foo_Bar` → `NEW_Bar`), and (b) a definition renamed but its `X_def`
unfold-lemma references left pointing at a name that no longer exists — which a
plain word-boundary pass *reports as clean* while the build then fails with
"Undefined fact `X_def`". The generator-vs-consumer asymmetry (a rename
generates the new derived names but does not rewrite the old derived
*references*) is what makes this a trap rather than an obvious error. Generic to
any system with tool-generated derived names keyed off a base identifier
(Isabelle `_def` / `.simps`, Lean `.rec`, generated struct accessors).
