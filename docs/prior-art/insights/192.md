# 192. Doc antiquotations cannot forward-reference same-theory lemmas

**Part:** Part X — Isabelle document hygiene
**Added:** 2026-06-29

## When it applies

You write a `text`/`section`/`subsection` block at the *top* of a theory that
mentions a lemma defined *later* in the same theory — a common, natural urge
when the intro paragraph wants to name the headline result the theory builds
to. If you reach for `@{thm[source] that_lemma}` the build fails with
`Undefined fact: "that_lemma"`, even though the lemma is right there further
down the file.

## What to do

Use the plain-name antiquotation `@{text that_lemma}` for any forward
reference. `@{thm}` / `@{thm[source]}` resolve their argument against the fact
table *at the position the `text` block is elaborated*, so they only see facts
already proved above; `@{text "..."}` is a pure pretty-printer that performs no
lookup and so happily prints a name that does not yet (or never will) exist as
a fact. Reserve `@{thm[source]}` for *backward* references (lemmas earlier in
the theory or in an imported one), where the cross-check that the name resolves
is a genuine benefit.

## Why / what it avoids

It avoids a wasted build cycle on an `Undefined fact` error that looks like a
typo but is really an ordering constraint, and it keeps the cross-checking
value of `@{thm[source]}` where it pays off (catching a stale backward
reference after a rename) instead of fighting it where it cannot work. The cost
of `@{text}` for a forward reference is only that a later rename of the target
will not be flagged in the intro prose — acceptable for a one-line headline
mention.

## The other trigger: a *backward* reference that a move turns undefined
*(2026-09-08 — same mechanism, and the one no static check covers.)*

The forward case above is caught by `make lint-latex`. The case it cannot
catch is a **hoist**: moving a block to a theory that does not import the
reference's home.

The asymmetry is what makes this likely rather than rare. A hoist moves an
entry *down* the import DAG, and down means strictly less in scope — so every
antiquotation in the moved block is a candidate, and the ones at risk are
exactly the references that were unremarkably backward before. Moving the
codec facts out of `Diagonal_Sweeps` broke two `\<^const>\<open>TP_TRS\<close>`
references, because `Diagonal_Transcript` sits *below* the tape roles; moving
`tab_block_cell` and three run lemmas broke two `\<^const>\<open>holds_word\<close>`
references, because neither destination imports `Diagonal_Transcript`. Four
occurrences across three moves in one session: a rate, not an accident.

**Nothing static sees it.** A proof-body citation graph does not read prose, so
`bin/hoist-scan.py` is blind to it by construction. `bin/split-plan.py` *does*
read prose edges, but only between the groups of the theory being cut — a
reference to a theory outside that cut is not an edge it models.
`make lint-latex` checks forward references *within* a theory. A backward
reference to a non-ancestor is none of the three, so **the build is the only
detector**, and it reports one per attempt.

**The fix is to demote, not to import.** `\<^const>\<open>holds_word\<close>` becomes
`\<open>holds_word\<close>`: the sentence still reads, and the theory does not acquire
a dependency for the sake of a word. Adding the import is the tempting move and
it is wrong — it re-couples two layers that a hoist has just separated, which
is the outcome the hoist existed to prevent. Same judgement `split-plan.py`'s
own docstring gives for a prose-only cross-group edge.
